# UNO 第一版玩法改造需求说明

本文记录将现有 Carrom 弹珠对局改造成 UNO 纸牌玩法的第一版需求边界。

客户端通讯协议草案见：

```text
caii-server/docs/uno-client-protocol-draft.md
```

规则来源：

```text
http://192.168.103.154:8080/uno_rule
```

## 1. 第一版目标

UNO 是全新的核心玩法，用来**完全替换现有 Carrom 弹珠对局**，不是作为新 `play_type` / 新 `room_type` 与 Carrom 并存。

现有项目原先是弹珠/物理对局：

```text
客户端/宿主机计算物理过程
服务器主要负责转发广播
机器人根据球局状态出杆
```

UNO 是纸牌游戏，第一版应调整为：

```text
服务器权威计算
客户端只提交操作请求
服务器校验操作合法性
服务器维护牌堆、手牌、当前出牌方向、当前玩家、惩罚累计等状态
服务器向客户端广播可见结果
服务器只向对应玩家下发自己的手牌
机器人服根据服务端同步的状态和自己的手牌做出牌决策
```

原因：

- 发牌必须由服务端随机。
- 手牌不能对所有玩家公开。
- 出牌是否合法必须由服务端校验。
- 摸牌结果必须由服务端决定。
- +2/+4 叠加、跳过、反转等状态必须服务端统一推进。
- 防止客户端作弊。

## 2. 第一版明确不做的规则

以下规则第一版暂不实现：

```text
Numbers Only
Shuffle Hands
Wild Draw Four 质疑
手动 UNO / 抓 UNO / 忘喊 UNO 罚摸
复杂匹配策略
纯机器人桌
```

### 2.1 Numbers Only

规则页中有 `只能出数字牌 Numbers Only`，第一版不做。

### 2.2 Shuffle Hands

规则页中有 `洗手牌 Shuffle Hands`，第一版不做。

### 2.3 Wild Draw Four 质疑

规则页中有 +4 质疑：

```text
质疑成功：出 +4 的玩家摸 4
质疑失败：质疑者摸 6
```

第一版不做质疑逻辑。也就是说：

```text
Wild Draw Four 打出后直接生效，不弹质疑流程。
```

### 2.4 UNO 喊牌

第一版采用自动 UNO：

```text
玩家剩余 1 张牌时，默认已喊 UNO。
不做手动 UNO 按钮。
不做其他玩家抓 UNO。
不做忘喊罚摸 2 张。
```

## 3. 牌堆规则

第一版使用标准 UNO 108 张牌。

### 3.1 颜色

```text
Red
Yellow
Green
Blue
Black / Wild
```

### 3.2 每种颜色牌

四种普通颜色：红、黄、绿、蓝。

每色：

```text
0：1 张
1-9：各 2 张
Skip：2 张
Reverse：2 张
Draw Two：2 张
```

每色共：

```text
1 + 9 * 2 + 3 * 2 = 25 张
```

四色合计：

```text
25 * 4 = 100 张
```

黑牌：

```text
Wild：4 张
Wild Draw Four：4 张
```

总计：

```text
100 + 8 = 108 张
```

---

## 4. 房间与匹配规则

第一版只做 4 人房。

```text
每桌固定 4 人。
不允许纯机器人桌。
```

### 4.1 匹配等待

第一版匹配逻辑先简化：

```text
玩家进入匹配池。
10 秒内尽量等待真人。
如果凑满 4 个真人，立即开局。
如果等待达到 10 秒但真人不足 4 个，则补机器人到 4 人并开局。
```

当前确认：

```text
4 人房中，10 秒后无论当前有几个真人，都补机器人开局。
但必须至少有 1 个真人。
不允许 0 真人纯机器人桌。
```

示例：

```text
1 真人等待 10 秒 -> 补 3 个机器人
2 真人等待 10 秒 -> 补 2 个机器人
3 真人等待 10 秒 -> 补 1 个机器人
4 真人提前凑齐 -> 不补机器人，立即开局
```

## 5. 开局发牌

开局时：

```text
每人 7 张手牌。
从 108 张牌堆随机洗牌后发牌。
```

初始牌堆流程：

```text
1. 创建标准 108 张牌。
2. 洗牌。
3. 按座位顺序每人发 7 张。
4. 从剩余牌堆翻开第一张作为弃牌堆顶部牌。
5. 初始牌一定不能是功能牌；如果翻到功能牌，放回/跳过后继续翻，直到翻到数字牌。
```

已确认：

```text
初始牌必须是数字牌，不能是 Skip / Reverse / +2 / Wild / +4。
```

## 6. 基本出牌规则

玩家回合内可以：

```text
出牌
摸牌
```

出牌合法性：

```text
普通颜色牌：颜色相同，或数字/符号相同，可以出。
Wild：任意时候可出，并选择下一轮颜色。
Wild Draw Four：第一版任意时候可出，并选择下一轮颜色，不做质疑。
```

摸牌规则：

```text
如果没有可出的牌，需要摸 1 张。
摸到的牌如果能出，可以立即出，也可以选择不出。
如果摸到的牌不能出，回合结束，轮到下一位。
如果摸到能出但玩家选择不出，也结束回合，轮到下一位。
```

已确认：

```text
玩家摸到牌后可以不出。
因此需要保留 GR_C_UNO_PASS_AFTER_DRAW。
```

## 7. 功能牌规则

第一版实现以下功能牌：

```text
Skip
Reverse
Draw Two
Wild
Wild Draw Four
```

### 7.1 Skip

```text
下一位玩家跳过回合。
当前玩家出牌后，轮到下下一位。
```

### 7.2 Reverse

4 人房中：

```text
改变出牌方向。
顺时针 -> 逆时针
逆时针 -> 顺时针
```

### 7.3 Draw Two

```text
下一位玩家需要摸 2 张并跳过回合。
但如果下一位玩家有 +2 或 +4，可以继续叠加。
```

### 7.4 Wild

```text
任意时候可出。
出牌者选择下一轮颜色。
不产生摸牌惩罚。
```

### 7.5 Wild Draw Four

第一版简单规则：

```text
任意时候可出。
出牌者选择下一轮颜色。
产生 +4 惩罚。
不做质疑。
```

## 8. +2 / +4 叠加规则

第一版采用简单版叠加规则：

```text
+2 和 +4 可以互相叠加。
被惩罚玩家如果手上有 +2 或 +4，可以继续打出一张摸牌牌。
如果不能或不出叠加牌，则摸累计牌数，并跳过回合。
摸完后轮到下一位玩家。
```

示例：

```text
A 出 +2，累计惩罚 = 2
B 出 +4，累计惩罚 = 6，并选择颜色
C 无法叠加，摸 6 张，跳过
轮到 D
```

叠加状态下允许出的牌：

```text
Draw Two
Wild Draw Four
```

叠加状态下不允许为了匹配颜色/数字出普通牌、Skip、Reverse、Wild。

## 9. 胜负与计分

第一版只做单轮胜负。

单轮结束条件：

```text
1. 任意玩家手牌数为 0，本轮立即结束，该玩家获胜。
2. 如果牌堆用完且无法继续摸牌，则本轮结束，按所有玩家手里剩余牌的分数判定胜负。
```

牌堆用完时胜负建议：

```text
手牌剩余分数最低的玩家获胜。
如果最低分并列，需要再确认并列规则；第一版可按最先达到该最低分的座位/当前顺序决定，或直接算平局。
```

计分规则按规则页：

```text
数字牌：牌面数字
Skip / Reverse / Draw Two：20 分
Wild / Wild Draw Four：50 分
```

第一版可以先实现：

```text
赢家获得其他 3 名玩家剩余手牌总分。
```

整局 500 分规则作为后续扩展，第一版不做。

```text
第一版不做多轮累计到 500 分。
谁先出完谁赢；如果牌堆用完，则按手里剩余牌分数判定。
```

## 10. 出牌倒计时与托管

第一版由服务器权威维护出牌倒计时。

```text
每个玩家回合操作时间：30 秒。
客户端只展示倒计时，不裁决超时。
服务端在回合开始时设置 turn_deadline_ms。
如果 30 秒内玩家没有完成操作，服务端将该玩家置为托管状态。
```

已确认：

```text
倒计时和超时裁决由服务器做。
玩家进入托管后，由服务器自动出牌。
客户端展示“托管中”状态提示，并在真人玩家处于托管时提供“取消托管”按钮。
```

托管自动出牌逻辑第一版暂时与机器人出牌逻辑一致：

```text
1. 有功能牌就出功能牌。
2. 没功能牌，就出和牌堆顶部同颜色的牌。
3. 还没有，就出和牌堆顶部同数字/同符号的牌。
4. 还没有，就摸牌。
5. 摸到的牌能出就出。
6. 摸到不能出，结束回合。
```

后续可扩展：

```text
真人托管策略和机器人策略分离。
真人托管可更保守，避免自动打出关键牌。
已补充第一版必需能力：真人玩家进入托管后可点击“取消托管”；手动开启托管可后续扩展。
```

## 11. 机器人逻辑

机器人上桌链路暂时不变：

```text
caiisvr 召唤机器人
caiirobotsvr 选择机器人
机器人发送进入游戏请求
caiisvr 将机器人绑定到桌子
```

改变的是机器人对局行为：从原先 Carrom 出杆逻辑改成 UNO 出牌决策。

第一版机器人策略：

```text
1. 有功能牌就出功能牌。
2. 没功能牌，就出和牌堆顶部同颜色的牌。
3. 还没有，就出和牌堆顶部同数字/同符号的牌。
4. 还没有，就摸牌。
5. 摸到的牌能出就出。
6. 摸到不能出，结束回合。
```

建议功能牌优先级：

```text
Wild Draw Four
Draw Two
Skip
Reverse
Wild
同颜色数字牌
同数字牌
摸牌
```

Wild / Wild Draw Four 选色策略：

```text
选择机器人手牌中数量最多的普通颜色。
如果没有普通颜色，随机选择红/黄/绿/蓝。
```

叠加状态下机器人策略：

```text
如果当前处于 +2/+4 累计惩罚状态：
  优先出 Wild Draw Four
  其次出 Draw Two
  如果没有可叠加牌，则摸累计牌数并跳过。
```

## 12. 服务端状态模型建议

UNO 桌子需要维护以下状态：

```text
房间/桌子 ID
4 个座位玩家
当前出牌玩家座位
出牌方向：顺时针/逆时针
牌堆 draw_pile
弃牌堆 discard_pile
每个玩家手牌 hand_cards
当前指定颜色 current_color
当前顶部牌 top_card
当前累计惩罚 draw_penalty_count
当前是否处于叠加状态 stacking_active
当前回合序号 turn_seq
当前回合截止时间 turn_deadline_ms
每个玩家是否托管 is_trustee
本轮积分
是否已结束
```

客户端可见数据：

```text
自己的完整手牌
其他玩家手牌数量
顶部弃牌
当前颜色
当前玩家
出牌方向
累计惩罚数量
每个玩家是否托管
当前玩家剩余倒计时/截止时间
最近一次操作
```

不能广播给所有人的数据：

```text
其他玩家具体手牌
剩余牌堆顺序
机器人手牌如果由服务端权威维护，也不应广播给真人客户端
```

## 13. 后续实现建议

因为 UNO 完全替换 Carrom，建议不要在旧 Carrom 物理对局逻辑上继续修补，而是在保留现有网络、登录、匹配、机器人上桌、广播通道的基础上，替换游戏桌内部状态机和游戏协议语义。

可复用：

```text
caiisvr / caiirobotsvr 服务进程
玩家进房/进桌基础链路
机器人上桌链路
mp 代理链路
日志、配置、DB/Redis 基础设施
Notify/Request 分发框架
```

应替换：

```text
Carrom 物理同步
puck/striker/出杆/球权物理计算
原先复杂球局机器人出杆逻辑
原先非 4 人 UNO 的匹配和桌子人数假设
```

建议按阶段实现。

### 阶段 1：纯服务端 UNO 状态机

```text
定义 Card / Deck / Hand / UnoTableState
实现洗牌、发牌、摸牌、出牌校验、回合推进
实现 Skip / Reverse / +2 / Wild / +4
实现 +2/+4 叠加
实现 30 秒回合倒计时
实现超时进入托管
实现托管自动出牌
实现单轮结束和计分
```

### 阶段 2：协议接入

```text
新增/调整 UNO 相关 proto
EnterGameResp 下发 UNO 初始状态
PlayCardReq / DrawCardReq / ChooseColor 等请求
广播 PlayCardNtf / DrawCardNtf / TurnChangedNtf / GameOverNtf
```

### 阶段 3：机器人接入

```text
caiisvr 在机器人回合通知 caiirobotsvr
caiirobotsvr 根据自己的手牌和公共牌面决策
caiirobotsvr 发送 PlayCardReq 或 DrawCardReq
```

### 阶段 4：匹配简化

```text
4 人桌
10 秒等待真人
10 秒后补机器人到 4 人
至少 1 个真人
不允许纯机器人桌
```

### 阶段 5：客户端 UI/交互适配

```text
显示手牌
显示其他玩家手牌数量
显示当前顶部牌和当前颜色
显示当前玩家
出牌/摸牌操作
Wild 选择颜色
自动 UNO 表现
游戏结束结算
```

## 14. 仍需确认的问题

以下问题在正式编码前还需要确认：

1. 初始翻开的第一张牌如果是功能牌，是否重新翻到数字牌？建议第一版重新翻数字牌。
2. 玩家有可出牌时，是否允许主动摸牌？建议第一版不允许。
3. 机器人 UNO 决策是在 `caiirobotsvr` 完成，还是第一版先在 `caiisvr` 内部直接模拟？为了沿用现有架构，建议仍放在 `caiirobotsvr`。
4. 牌堆用完且剩余手牌分数最低者并列时，如何处理并列？

## 15. 已确认决策

```text
UNO 玩法完全替换 Carrom。
不做 Carrom / UNO 双玩法并存。
第一版以 UNO 4 人房为唯一核心对局。
服务端权威维护 30 秒出牌倒计时。
超时后玩家进入托管，由服务端按机器人逻辑自动出牌。
客户端展示托管中状态，并提供取消托管入口，避免玩家一旦托管就无法恢复手动操作。
```
