# UNO 待办清单

> 文档性质：需求待办 / 架构风险记录。以下内容尚未完成方案设计和实现验证。

## 服务器更新、重启与版本隔离

### 1. 对局中服务器更新或重启时的玩家处理

上线后，如果玩家正在同一 UNO 房间/牌桌中进行对局，而 GameServer 发生更新、重启或异常退出，需要明确并实现完整策略：

- 服务器重启前是否进入维护状态，停止新玩家进入；
- 已经匹配或已经开局的牌桌如何处理；
- 是等待原牌局完成、迁移牌局，还是直接结束并结算/退款；
- 玩家断线重连的最大时间和重连入口；
- 服务器恢复后是否能够恢复牌桌、回合、手牌、牌堆和托管状态；
- 重启期间玩家端显示的状态、错误码和补偿规则；
- 结算、入场费、金币扣除不能重复执行；
- 机器人、直播、聊天频道和观众连接如何处理。

需要形成上线前的发布/重启 Runbook，并至少完成一次真实演练。

### 2. 大规模更新时的旧房间与新房间隔离

大规模发布可能同时存在两套服务：

- 老玩家继续在旧服务和旧房间中完成牌局；
- 新玩家进入新服务和新房间；
- 两套服务不能让玩家、牌桌、机器人、直播或聊天错误串线。

需要确认并实现以下内容：

- 房间/牌桌是否通过客户端版本号或服务版本号进行分流；
- Hall 如何根据版本把玩家分配到不同的 GameServer；
- 老玩家重连时如何固定回旧服务和旧房间；
- `room_section_id`、room 配置、GameIP/Mpport、bout_id 是否共同承担隔离职责；
- 新老版本协议是否兼容，哪些版本可以进入同一牌桌；
- 旧版本服务何时下线，以及下线前如何排空旧牌桌；
- 直播列表、观战和 Chat 是否也必须按服务版本隔离。

## 当前代码核对结果（仅记录，不代表已完成）

当前代码存在通用的版本兼容配置：

```ini
[CompatibleVersion]
area=0-1.8|1.9-1.15|1.16-1.25|1.26
```

相关实现位于：

- `caiisvr/base/game_table.cpp`：`CheckVersionInArea` 及进入牌桌时的版本兼容判断；
- `caiisvr/manager/game_config.h/.cpp`：`CompatibleVersionArea` 配置加载；
- `caiisvr/ini/caiisvr_busi.ini`：兼容版本区间配置。

目前只能确认这里用于**同桌客户端版本兼容性判断**，尚不能据此确认它已经实现了“版本对应不同房间/不同服务器”的完整分流。

后续需要继续核对 Hall、房间配置、`room_section_id`、GameIP/Mpport 和重连链路，确认实际的版本分房机制。
