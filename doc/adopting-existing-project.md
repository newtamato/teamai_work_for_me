# 已有项目渐进接入

先备份并检查仓库状态，在独立任务工作树进行接入，不覆盖原AGENTS、规则或知识。维护者确定授权策略与检查命令，原业务代码和存储布局不需要改为Node。

1. **入口整合**：将本模板入口索引合入现有AGENTS，按主题合并规则。同一约束只维护一份，保留项目真实的部署、数据库和页面验收要求。
2. **知识整理**：保留现有有来源的条目，补索引、范围与状态；私有历史不能原样迁入Git。不将未知事实自动标active。
3. **流程固化**：选择一个反复使用且验证过的流程建立Skill，其余工作按create/update/reuse/defer/none审查，防止一次搬入大量重复技能。
4. **工程守卫**：引入scripts、tests及agent.config，把必要检查加入checks。先在任务分支验证正常与拒绝行为，再将merge-check接入现有平台CI。旧任务审计不追填虚构字段，新交付采用新回执。
5. **能力同步**：有业务CLI时再开启capabilities；登记源码来源与可调用命令、未暴露原因。运行快照检查，修改能力时同步help/schema/示例/Skill。
6. **定时迁移**：维护某个任务时将长流程移入Skill，任务只保留调用与参数。读回配置并保留未授权的时间、绑定和暂停状态，不批量重建其他任务。
7. **发布接入**：在发布计划中登记现有步骤并链接业务验证文档；此模板不自动执行这些计划。不复制其他项目的管理员强制审核授权。

每阶段先形成可审查结果与验证证据，必要时分MR。目录冲突要人工合并，不能递归覆盖。接入完成后测试一个从任务创建、复盘、检查到merge-check的完整闭环，并声明仍未接入的平台保护或业务验证缺口。
