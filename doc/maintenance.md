# 维护与升级

## 权威位置

AGENTS只索引；rules维护约束；memory维护知识；Skill维护重复步骤；README和doc维护使用与设计说明。模板工具更新不自动复制到其他项目；记录采用版本，审查差异后迁移，保留项目本身的策略。

## 变化如何联动

| 变化 | 同步内容 | 验证 |
|---|---|---|
| 规则变化 | 入口索引、相关文档 | 链接与实际权限边界 |
| 知识纠正 | 原条目、索引、替代或撤回状态 | 来源与最近核实日期 |
| Skill步骤变化 | version、updated_at、示例和资源 | 正常、边界、失败场景 |
| 业务能力变化 | 契约、help/schema、Skill、能力快照 | capabilities check及cliReview |
| 定时触发变化 | 平台时间/状态/参数或引用 | 私有备份、回读、实际运行另报 |
| 工程守卫变化 | 脚本、测试、说明 | 合成正常与拒绝场景 |

Skill改动不自动启用任务。未验证的经验降pending；历史对话蒸馏属于后续可独立设计的能力，当前只由任务Agent主动复盘。

## 配置与依赖

工具使用Node22内置模块。默认main和任务前缀taskPrefix是工程约束，变更需同时扩展工具与测试。checks仅执行维护者信任的本地命令，不把外部不可信内容直接拼成shell。

release配置只是发布计划插口：`npm run agent -- release-plan`展示计划，实际平台合并和部署由维护者的适配器执行并核验。不得将计划enabled写成发布已成功。

能力登记支持已声明来源的指纹关联，不能自动发现任意语言中的所有业务接口。更新快照前审查实质变化，不通过刷新指纹掩盖漏命令。

## 守卫失败

缺知识复盘：重新读索引，填写真实updated或none。Skill变动未覆盖：补create/update和实际validation，不虚构测试。源码指纹过期：重审实际diff、同步能力、重做复盘与验收。脏目录：保留现场并由负责人提交或明确处理，不reset/clean。基线落后：fetch真实远程，处理冲突后验证。

本地门禁不等于平台强制；没有CI/保护分支时可被绕过。结构正确不等于内容真实，语义、授权和正式业务验收仍由主代理及维护者负责。保留任务分支与运行记录，清理另行授权。
