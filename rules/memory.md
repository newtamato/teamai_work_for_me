# 项目记忆规则

## 读取与边界

每次接手读 [索引](../memory/INDEX.md)，用关键词检索相关主题，不全量加载。优先 `active`；`pending`仅作待核实线索；`superseded`和`revoked`仅用于追溯。检查适用范围与最近核实日期，容易变化的事实以当前代码和工具状态为准。

项目文件记忆与个人/平台记忆、业务私有存储独立管理，不自动复制。用户指令、规则与实际证据优先于旧记忆；冲突写清证据，不能静默择一。自动更新指当前Agent在任务中维护文件，不是后台模型服务。

## 主动沉淀

在项目维护者已授权本规则范围内的本地知识维护时，任务中及交付前主动保存稳定事实、长期偏好、设计取舍、有验证依据的工程经验。用户本次只读或禁止记录时优先遵从。只要求记录不等于授权实施记录中的动作。

收到纠正、长期决定、重复问题或验证根因时提炼候选。用户陈述标 `user-reported`；代码或测试核实注明方式与定位；推测只在确需追踪时以 `pending`保留。原始对话、进度流水、测试输出和一次性结果不沉淀。

内容必须适合提交Git：不放真实账户、私有业务原件、身份标识、凭据或日志；这些保存在项目确认的私有存储。记忆只记脱敏定位及机制知识。

## 写入与失效

1. 搜索去重，使用 [模板](../memory/TEMPLATE.md)，一条可独立检索的主题一个文件，命名 `YYYY-MM-DD-short-topic.md`。
2. 写明类型、状态、日期、范围、关键词、来源、验证方式、最近核实日期、证据、下次行动与失效条件，同次更新索引。
3. 同主题更新原文件并追加变更记录。结论替代时旧条目标 `superseded`并链接新条目；用户撤回或证据证明错误标 `revoked`；过期未核实改 `pending`。不删除历史来绕过审查。
4. 事实进入memory，约束进入rules，可重复操作进入Skill。已有权威规则用链接，不复制第二份正文。

## 交付复盘

每个修改任务完成前检查“学到了什么、证据是什么、是否复用、旧知识是否失效、Skill是否应固化”。在任务工作树生成 `.delivery/memory/<task>.json`；它是审计回执，不加入知识索引。

使用 [复盘输入示例](../templates/delivery/review-input.json)，执行：

```sh
npm run agent -- review --input .runtime/review-input.json
npm run check
```

memory结论为 `updated`或`none`；updated覆盖实际变动条目，none说明没有新增知识的具体原因且无条目变更。`skillReview`为非空判断数组，见 [Skill规则](skills.md)；能力变动按 [开发规范](development.md)带 `cliReview`。任务、基线、指纹由工具填写，不编造。

改动内容或基线变化会使旧回执与验收失效，需重新复盘和验证。主稳定分支只核验知识结构，不制造空任务回执。子代理返回候选，主代理统一维护。

工具能检查字段、链接、索引和变动关系，不能证明记忆真实、有价值或已被理解。保留none防止垃圾知识；本地检查也不能阻止管理员或其他机器绕过。
