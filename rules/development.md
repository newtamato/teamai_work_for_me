# 开发、能力同步与交付

## 工作树与隔离

默认分支固定main、任务前缀由agent.config.json的taskPrefix配置（默认codex/，可按agent改为空或其它前缀）；主目录保持已验收稳定版本。正常修改使用 `npm run agent -- task create <slug>`，名称小写字母数字连字符；工具具体前置条件以help为准。首次空仓库初始化可在主目录完成一次bootstrap，形成基线后恢复任务流程。

接手先检查脏文件、分支及新鲜远程基线；已有任务副本复用，不复制或清理别人未提交改动。不直接push默认分支，不自动reset/clean。任务命令显式cwd，各自独立依赖、运行日志与测试产物。

业务服务、端口、数据库和文件存储由接入项目定义。生产写与开发隔离，测试用合成数据或允许的快照，不回灌生产；本模板不提供数据库迁移或固定服务端口。保留已合并工作树和审计记录，清理须明确授权并先检查目标、未提交内容及应保留数据。

## CLI与同步复盘

工程CLI为 `npm run agent -- help`。业务CLI由项目维护者提供；Agent先查help/schema再执行，不用私自import代码替代已有正式能力。输入契约、读写属性、输出、错误码、分页、幂等和写后回读要明确。

新增/更新能力同任务审查CLI、help、schema、示例、配套Skill和测试；兼容新增升MINOR、修复升PATCH，不兼容变化升MAJOR。单一契约生成能力说明可避免文档漂移。

`capabilities.enabled`默认false。启用后配置源路径与命令关联，未暴露来源写具体exclusions理由；执行 `capabilities sync`生成确定性快照，`capabilities check`检测过期与漏登记。来源变更在复盘带cliReview：updated或unchanged、具体reason、evidence和已登记commands；单更新指纹不等于完成契约审查。登记不自动生成业务命令。

## 验证门禁

停止并行写入，先完成记忆和Skill复盘；启用能力检查时也完成CLI复盘。执行 `npm run agent -- review --input .runtime/review-input.json`，再 `npm run check`。测试失败修复后重验；不要重复执行同一有效验证来凑证据。

Node22工程测试使用内置测试框架，接入项目在checks中声明必要检查。新增行为应验证正常、边界与失败；页面交互改动应实际检查页面，不能用API成功替代；数据改动验证迁移、完整性与回读，避免只测试镜像实现。

变更内容或基线变化使复盘和验收失效，重新审查并执行受影响检查。提交后执行 `npm run agent -- merge-check`核验；命令不替代平台审查。不能把失败状态注册为通过。

## 平台与发布

提交任务分支，创建面向默认分支的MR/PR，正文说明问题、结果、验证、数据影响与限制。合并/外部发布依用户明确授权或维护者书面配置；不复制任何管理员强制审核或自动部署权限。

配置repository只是声明目标，不自动安装平台适配器。将merge-check接入平台CI/受保护分支，才能约束其他机器；本地工具不能防管理员绕过。

release默认关闭。启用时维护者配置实际钩子及授权策略，合并后先同步正确且洁净的默认分支，按业务需要备份、迁移、部署并核验版本与真实流程。模板没有自动平台合并或默认生产发布，不将钩子配置写成已完成部署。

最终区分“已验证、已提交、已合并、已同步、已发布”及缺口；平台不可用时保留可审查结果，不直接push默认分支绕过。
