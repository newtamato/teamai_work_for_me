# 测试

## 现状
目前还没有自动化测试。目标是从「手动联调」逐步过渡到「协议回归测试 + 单元测试」。

## 三步走

### 1. 协议联调（先做这个）
写一个独立的小工具模拟客户端/服务端，对着 rules/api-contract.md 逐条验证：
- 帧格式是否正确（长度头 + msg_id + protobuf）
- 每个接口的请求/响应字段是否一致
- 粘包/半包、异常断开、心跳超时等边界

### 2. 服务端单元测试
- 框架：GoogleTest
- 优先覆盖：编解码、帧拆包、handler 的业务逻辑

### 3. 客户端单元测试
- 框架：Unity Test Framework / NUnit
- 优先覆盖：协议编解码、网络层拆包、UI 之外的可测逻辑

## 每次提测/验收必须验证
- [ ] 新接口已对着 api-contract.md 联调通过
- [ ] 断线重连、心跳、超时等异常路径通过
- [ ] 客户端和服务端协议版本一致

## 发现的坑
联调中遇到任何「两端对不上」的问题，结束后用 `teamai contribute` 沉淀成 learnings，方便团队复用。
