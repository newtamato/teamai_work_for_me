# 定时治理审计

这是无业务数据的合成示例。用于演示“触发器一句调用，Skill维护完整过程”。指定date优先，否则在开始时固定Asia/Shanghai日期作为报告标签；标签不选择业务数据。read-only检查不自动修复。

## 前置与输入

运行在稳定main目录，读AGENTS、[定时规则](../../../rules/automations.md)及配置。可选输入date为YYYY-MM-DD；非法日期停止并说明。任务配置不赋予外部写入、发消息或部署权限。

## 执行

1. `npm run agent -- task status`确认目录与main状态。若是任务分支或有进行中的修改，报告跳过，避免把尚未完成的任务当作正式缺陷。
2. `npm run agent -- memory-check`检查条目、索引和链接。能力登记启用时执行 `npm run agent -- capabilities check`。
3. 不运行可能写验收产物或业务状态的完整check；工程检查必须由维护者确认只读才可扩展本流程。只使用CLI，不自行import工具实现或修改数据库。
4. 输出固定日期标签、代码版本或基线（如CLI返回）、已执行命令、通过/失败状态和应由下一修改任务处理的缺口。缺数据标未知，不制造零缺陷结论。
5. 相同日期、相同来源没有变化时复用结果或简短说明，幂等只读操作可重复执行。外部通知和持久化需单独授权/接入，当前只返回给调用方。

## 失败与验收

缺Node、错误目录、CLI失败时停止相应步骤，报告退出状态；不偷偷修复或重建任务。正常应报告结构检查通过，合成坏链接应报告失败，任务分支应跳过。定时配置校验不代表调度器已安装或真实运行成功。
